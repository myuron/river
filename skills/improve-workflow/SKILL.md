# improve-workflow

Turn recurring friction into durable fixes. The goal is fewer human interventions and fewer wasted steps per `/ship`, not more instructions.

## 1. Collect

- Read `.claude/friction.md`. New entries are appended at the bottom, so only entries below the last `<!-- processed ... -->` line are new; if there is none, all entries are new. If there are fewer than 3 new entries, say so and ask whether to continue anyway.
- Read the current workflow so proposals fit what exists: `skills/*/SKILL.md`, `.claude/agents/*.md`, `.claude/settings.json` and `.claude/hooks/`, `CLAUDE.md`, `.oxlintrc.json`.
- Optional, when an entry is too vague to act on: look up the matching session in `~/.claude/projects/<project-dir>/*.jsonl` (by date) for the concrete context.

## 2. Find patterns

Group the new entries' items by root cause, not by wording. A pattern qualifies when it appears in **2+ runs**, or once if it caused a blocker/wrong behavior that reached a PR or a stopped run. List one-offs separately and don't act on them.

## 3. Choose the fix

Pick the lightest fix that reliably prevents the pattern:

| Pattern                                                    | Fix                                                                         |
| ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| The user repeats the same instruction or correction        | Add the rule to `CLAUDE.md` (repo-wide) or the relevant skill (step-local)  |
| A written rule keeps being ignored                         | Enforce it: hook in `.claude/hooks/`, or an oxlint rule in `.oxlintrc.json` |
| `reviewer` flags the same kind of issue repeatedly         | Prevent it earlier: lint rule, or a conventions skill used while coding     |
| A human found a problem `reviewer` missed                  | Add a check item to `.claude/agents/reviewer.md`                            |
| Same investigation every run, eating context               | Extract a read-only research agent into `.claude/agents/`                   |
| Asking questions the repo could answer / missing knowledge | Write the answer down (CLAUDE.md or a skill section)                        |
| A phase's steps vary or get skipped                        | Make the phase its own skill, or tighten its steps in `ship`                |
| `just ci` keeps failing the same way                       | Add the fix pattern to `verify`, or catch it earlier with a hook            |

Also look for the reverse: instructions that never mattered or that caused over-cautious behavior. Removing them is a valid improvement.

## 4. Propose, then apply

Present a numbered list before changing anything:

```
1. <pattern> — seen in <runs>
   Fix: <file> — <what changes>
   Expected effect: <which friction disappears>
```

Plus the one-offs you're deliberately not acting on. **Wait for the user to choose** which proposals to apply.

Then apply the chosen ones:

- Skills live in `skills/<name>/SKILL.md` (tracked). `.claude/skills/` is generated by agent-skills-nix from `flake.nix` — never edit it directly. New skills under `skills/` are picked up automatically, but must be `git add`ed before the flake can see them; then re-enter the dev shell (`direnv reload`) to sync.
- Keep skills short and imperative; explain the why when a rule isn't obvious.
- Test new or changed hooks by piping sample JSON into the script, as in the existing hooks.
- Run `nix fmt` on changed files.

## 5. Close the loop

- Append a marker line at the end of `.claude/friction.md` so the entries just reviewed count as processed: `<!-- processed YYYY-MM-DD: applied #1, #3; skipped #2 -->`. Don't delete entries.
- Commit the workflow changes with the `commit-pr` skill as `chore(workflow): ...`, listing each pattern and its fix in the PR body.
